## Model-layer conformance

Derived from Anthropic's guidance for Claude Fable 5.2 (audited 2026-11-09). Ledger and sources: `~/.claude/CONFORMANCE.md`.

**Stated as instruction CLASSES, never as named plugins.** Any skill, plugin, command or harness text in a class below is superseded, whoever ships it and whenever it arrives. Anthropic on 5.2: "some instructions written for earlier models raised cost, caused side effects, or no longer had an effect." Detector: `python3 ~/.claude/skills/anthropic-conformance/scripts/scan-superseded.py` (covers A to G; H and I are checked by reading). A hit is a line to rule on, not a defect.

**Supplied by the harness on Fable 5.2, do not restate:** finish the whole task and work through ordinary obstacles while leaving deliberate blockers alone; act when you have enough information; confirm hard-to-reverse and outward-facing actions, with approval scoped to the action named; report outcomes faithfully with the failing output; question and drop a stale caution in memory or notes; the cost-first subagent description; the reminder after a long silent stretch; the memory-system rules; "you don't need to wrap up early". All were read in a Claude Code 2.1.321 session's system prompt on 2026-11-09.

**Three 5.2 behaviors the harness does not cover, one line each.**

1. *Code ownership.* When the prompt says nothing about who owns the code, 5.2 adds to the existing structure, even when that repeats code, and reports nearby problems instead of fixing them. That default is right for someone else's repository, so the vendor sentence "This codebase is yours" is deliberately not used (it costs about 1.5 times the output tokens and brings unrequested changes). Before adding a helper, search for the one that exists.
2. *Approvals are read literally.* A go-ahead should name its action, and a bare "continue" is weaker than "yes, run X on Y". Read an approval rule for the exact actions it lists and no wider.
3. *Reports stand alone.* The reader of a final report has not seen the tool calls. Lead with the key point, use full sentences, and use no term invented during the work.

**Effort.** Anthropic: start at `high`, where "most of the gain in capability is already present"; `medium` for interactive coding and everyday work; `low` for well-specified tasks and fast subagents, scoring close to Fable 5.1 at higher levels; `xhigh` only where a gain was measured (slight gain, many more tokens); `max` for measuring the ceiling. Claude Code's own default for 5.2 is `medium`, so a saved `high` is a choice, not the default. Level names do not carry over from 5.1 or Opus 5.5. Early stopping is more likely at `low` and `medium`. Effort barely changes reply length; use the prompt for that.

**Claude Code mechanics that are specific to 5.2.**

- *Advisor.* A Fable 5.2 main thread accepts only a Fable 5.2 advisor; a lower advisor is silently not attached. Each advisor call re-reads the whole conversation uncached at Fable rates. Subagents inherit the configured advisor.
- *Leaving 5.2 mid-conversation loses its reasoning.* No other model reads 5.2 thinking blocks, so a `/model` switch or a classifier fallback continues without them. After a fallback the session stays on the fallback model (Opus 4.8 for a cyber flag, Opus 5 for a bio flag) until `/model` is run.
- *Refusal categories:* `cyber`, `bio`, `frontier_llm` (work that could help develop competing AI models; model-training projects are the likely surface), `reasoning_extraction`, `general_harms`. Benign security and life-sciences work can trigger the first two; that is routing, not an account flag.
- *Subagents.* A fork runs on the session's model, so on a 5.2 main thread a fork is a Fable agent. Check which model every other subagent defaults to.

**Model choice.** Anthropic's ordering is unchanged: start most work on Opus 5.5, and move to Fable 5.2 for demanding reasoning, long-horizon agentic work, leading many subagents, long unattended runs, or when Opus at higher effort still falls short. Fable 5.2 costs $8/$40 per million tokens against Opus 5.5's $4/$20. Which tier the main thread runs on is the user's routing table, not this profile.

**Precedence that makes it work:** user instructions (this file) outrank skills, which outrank default behavior. No plugin needs to cooperate.

**Expiry.** Each class is retired when Anthropic's guidance for the current model no longer supports it. A plugin update triggers a re-scan, not a re-derivation. A new Fable point release triggers a re-derivation.
