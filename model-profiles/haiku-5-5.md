## Model-layer conformance

Derived from Anthropic's guidance for the model in use (Haiku 5.5, audited 2026-10-07). Ledger and sources: `~/.claude/CONFORMANCE.md`.

**Stated as instruction CLASSES, never as named plugins.** Any skill, plugin, command, or harness text falling in a class below is superseded, whoever ships it and whenever it arrives, including plugins installed after this was written. Named examples are illustrative, never the definition. The Haiku 5.5 page is short and covers eight topics; where it is silent the class is carried from the Sonnet 5.5 and Opus 5.5 profiles and marked as carried.

Detector: `python3 ~/.claude/skills/anthropic-conformance/scripts/scan-superseded.py` lists every installed skill carrying one of these classes. Regexes over-match, so a hit is a line to rule on, not a defect.

Only if no real check can run here, say which one you did not run and why"), which improved performance in its testing at the cost of more tokens. **Supplied by the harness on Haiku 5.5: not observed.** No Haiku main-thread session has been read. On the first one, check the system prompt for the same items the Opus 5.5 profile lists (act when you have enough information, faithful reports, confirm before irreversible actions, "Finishing work", `<pasted_content>`, memory rules, today's date) and move anything present out of the local lines below.

**Two local lines, each a vendor paragraph the harness is not known to supply.** (1) *Turn endings and scope.* "With a long coding-agent system prompt at `low` effort, it sometimes stops early and hands the task back to the user", and Claude Code's system prompt is long. Vendor wording: keep working until everything the user asked for is done, and only stop to ask when you can't go on without the user or before a risky step (the push gate). When the work asked for is done and checked, stop and report; don't add features, docs, or refactors that weren't asked for, and mention one at the end instead of doing it. Raising `low` to `medium` roughly halved early stopping in Anthropic's test and more than doubled output tokens. (2) *Search before answering anything that can have changed.* Vendor wording, most needed at `low` effort and with a long system prompt: your training data ends well before today's date; records, office holders, prices, versions, rules and anything "latest" may have changed since then, so search for those before you answer, even when you feel sure; facts that can't change need no search. Do not turn this into "search every factual question": that instruction doubled needless searches with no gain in correct answers.

**Briefing a Haiku subagent** (for the model writing the brief; the subagent never sees this file). Give it today's date when it has a search tool. Never relay the user's words inside a tool result: Haiku 5.5 is "trained to resist prompt injection through tool results" and can ignore them there. Keep the task narrow and name the finish line; at `low` it is more likely "to skip a search, stop early, or skip a check". If it must change code at `low` or `medium`, include the class A check paragraph.

**Effort.** Haiku 5.5 is the first Haiku with effort levels; all five are supported and `medium` is the default on the Claude API and in Claude Code. Start at `medium` for most work, including agentic coding. `low` for chat, short tool tasks and simple high-volume requests. `high` for knowledge work, longer agent tasks and strict instruction following. `xhigh`/`max` only where a gain was measured, "and compare them with Claude Sonnet 5.5 on performance, cost, and speed". To get less thinking, lower effort. At `xhigh` in multi-turn chat the model sometimes puts its whole answer in thinking and ends the turn with no visible text. A Haiku subagent started from this machine inherits the session effort unless the Agent call passes `effort` (Claude Code 2.1.292). **Unverified:** whether the top-level `effortLevel: high` in `settings.json` applies to a `/model haiku` session; the model-config page exempts only Opus 5.5 from it, which implies it does.

**Model choice.** Haiku 5.5 is $0.10/$0.50 per million tokens for prompts up to 100K tokens and $0.50/$2.50 above that (cache reads $0.01 and $0.05), against Sonnet 5.5 at $2/$10: 20 times cheaper per token on a short prompt, 4 times on a long one, and a Claude Code agent's prompt is often long. **It is not a rung in the local coding routing table.** Anthropic: "Sonnet 5.5 and Opus 5.5 remain better choices for complex agentic coding tasks like those measured by Terminal-Bench 4.0", and the chart agrees at every level from `medium` up: Haiku `medium` 20.3 and Sonnet `medium` 28.8 both cost $0.68 per attempt, and Sonnet `high` (43.0 @ $1.46) beats Haiku `max` (39.2 @ $2.64) for less. Where it wins is narrow non-coding work: on GDPval-AA Haiku `high` scores 1420 Elo at $0.09 per task against Sonnet `medium` 1324 at $0.27, and on OSWorld Haiku `high` 61.3 at $0.18 against Sonnet `low` 57.9 at $0.68. Local use: a per-call `model: haiku` subagent for lookups, extraction, classification, log and document summaries, and browser work, the uses Anthropic names ("compaction, summarization, or subagent work"). Routing for coding stays as the Sonnet 5.5 profile and CLAUDE.md state it.

**Precedence that makes it work:** user instructions (this file) outrank skills, which outrank default behavior. No plugin needs to cooperate.

**Expiry.** Each class is retired when Anthropic's guidance for the current model no longer supports it, not when any particular plugin changes. Plugin updates trigger a re-scan, not a re-derivation. Recorded per audit in the ledger.
