## Model-layer conformance

Derived from Anthropic's guidance for the model in use (Opus 5.5, audited 2026-09-22). Ledger and sources: `~/.claude/CONFORMANCE.md`.

**Stated as instruction CLASSES, never as named plugins.** Any skill, plugin, command, or harness text falling in a class below is superseded, whoever ships it and whenever it arrives, including plugins installed after this was written. Named examples are illustrative, never the definition. Anthropic on 5.5: "Existing Claude Opus 5 prompts should perform well without changes, and the patterns in Prompting Claude Opus 5 remain a reasonable starting point." So the Opus 5 classes carry, with the changes marked below.

Detector: `python3 ~/.claude/skills/anthropic-conformance/scripts/scan-superseded.py` lists every installed skill carrying one of these classes. Regexes over-match, so a hit is a line to rule on, not a defect.

| # | Superseded class | What survives on Opus 5.5 |
|---|---|---|
| **A** | Mandated verification before completion claims: "run the verification command before claiming success", Iron Laws, evidence gates | Never *claim* a command passed without having run it; the harness already says to report outcomes faithfully. Opus 5 verifies its own work unprompted and 5.5 does so at least as well; a mandatory step on top causes over-verification |
| **B** | Standing review gates: "request review after every task", reviewer-as-ritual, a subagent to double-check work you just did | Dispatch a reviewer when the change is risky, wide, or you can name why you distrust it. 5.5 reviews with "more bugs caught … and fewer false alarms", so a review you do dispatch is worth more, not needed more often. On a long unattended run, keep the task's parts in a checklist and check it before ending a turn; that is Anthropic's 5.5 mechanism for long runs, not a verifier ritual. Prefer a file (such as `TASKS.md`) over the to-do tool when the run may outlast a compaction: Anthropic's 5.5 playbook notes the file survives summarization. One standing point is endorsed: before a diff goes to a human reviewer (a client PR), review it first; the same playbook recommends this for 5.5 |
| **C** | Delegate-by-default for the work itself: "2+ independent tasks means parallel agents", "always use subagents", pushing implementation down by reflex | Delegate large, genuinely independent tracks; do not delegate what a handful of your own tool calls finishes. 5.5 "sustains long-running autonomous work … with parallel subagents and little oversight", so a real parallel track is a good fit. No local override since 2026-09-22: the custom agent stack was retired for Claude Code's built-in agents |
| **D** | Re-check instructions: "double-check your answer", "re-verify before responding" | Nothing. Carried from Opus 5: these compound with the model's own self-correction |
| **E** | Mandatory-invocation thresholds: "1% chance means you MUST invoke", "before ANY response", two-document rituals for small tasks | Invoke a skill when the task is one it covers. A skill check never gates a clarifying question. **LOCAL extension**; Anthropic states no rule here |
| **F** | Fixed-template padding in deliverables: required Bottom Line / Key Principles / Real-World Impact sections | Match length to what the task needs. 5.5 finishes tasks in fewer tokens and its reports "say plainly what it did, what it found, and what it needs from you" |
| **G** | **New on Opus 5.5** (it was Fable-only). Instructions to reproduce, echo, transcribe or "show" internal reasoning as response text, or to write reasoning out as a substitute for thinking | Nothing. These trip the `reasoning_extraction` classifier, and server-side fallback does not retry that category. Thinking is always on; read thinking blocks if visibility is needed |

**Supplied by the harness on Opus 5.5 (observed in the session system prompt, Claude Code 2.1.280, re-observed 2.1.291); do not restate:** act when you have enough information (no re-deriving, no re-litigating, no surveying options you will not pursue); report outcomes faithfully, including failures and skipped steps; confirm before hard-to-reverse or outward actions; turn endings, since 2.1.291 at the latest (a "Finishing work" section: do not stop while work is owed, put status notes and recommendations beside the next step, stop only when nothing can move without the user or the blocker is deliberate; this was local line 1 until 2026-10-05); the `<pasted_content>` rule, verbatim from Anthropic's 5.5 page; the memory rules; "you don't need to wrap up early" on context; and a mid-turn "the user hasn't heard from you in a while" reminder, which is the 5.5 page's progress-update lever. **No longer supplied:** the Opus 5 "do not call the Agent tool unless asked" line is absent on this build, so the old harness conflict with the delegation stack is gone. The Opus 5 scope and correction-narration lines are absent too; scope is covered by the code-quality table in CLAUDE.md.

**One local line, because 5.5 has the behavior and the harness does not cover it.** *Scope.* Deliver what was asked at the scope intended; if a better approach exists, say so in a sentence and continue with the task as asked.

**Effort.** 5.5 defaults to `medium`, not `high`, and the names do not map across models: 5.5 at `medium` "matches or exceeds Claude Opus 5 at `high`" on coding and knowledge work, and at a given level it thinks more per turn than Opus 5, most of all at `xhigh` and `max`. Reserve `xhigh`/`max` for work where a quality gain was measured. To get less thinking, lower effort; prompt lines asking for less or more thinking are less reliable, and "think carefully before answering" lines add latency with no measured quality gain, so do not add them. Effort controls thinking depth, not response length or scope. Main thread and subagents: `medium`, the vendor default, set by the user on 2026-09-23 (it was `high` from 2026-09-22).

**Precedence that makes it work:** user instructions (this file) outrank skills, which outrank default behavior. No plugin needs to cooperate.

**Expiry.** Each class is retired when Anthropic's guidance for the current model no longer supports it, not when any particular plugin changes. Plugin updates trigger a re-scan, not a re-derivation. Recorded per audit in the ledger.
