## Model-layer conformance

Derived from Anthropic's guidance for the model in use (Sonnet 5.5, audited 2026-09-28). Ledger and sources: `~/.claude/CONFORMANCE.md`.

**Stated as instruction CLASSES, never as named plugins.** Any skill, plugin, command, or harness text falling in a class below is superseded, whoever ships it and whenever it arrives, including plugins installed after this was written. Named examples are illustrative, never the definition.

Detector: `python3 ~/.claude/skills/anthropic-conformance/scripts/scan-superseded.py` lists every installed skill carrying one of these classes. Regexes over-match, so a hit is a line to rule on, not a defect.

| # | Superseded class | What survives on Sonnet 5.5 |
|---|---|---|
| **A** | Mandated verification before completion claims: "run the verification command before claiming success", Iron Laws, evidence gates | Sonnet 5.5 "generally checks its work before it reports a change as done". Never *claim* a command passed without having run it. The 5.5 page reports skipped checks only at `low` effort, and says to add its "run a real check before reporting done" paragraph only if you see changes reported complete without test or build output. Nothing is reported missing at `medium` and above, so a mandatory step there duplicates the model's own checking (the over-verification warning is from the Opus 5 page and is carried, not restated by the 5.5 page) |
| **B** | Standing review gates: "request review after every task", reviewer-as-ritual, a subagent to double-check work you just did | Dispatch a reviewer when the change is risky, wide, or you can name why you distrust it. At `xhigh` and `max` the model starts review rounds on its own, sometimes with subagents. Anthropic's test at `max` found that telling it not to launch reviewer subagents unless asked cut session cost by about a third with no change in quality; the line reduces self-started review rounds but does not remove them. Two points carried from the Opus 5.5 playbook, with no Sonnet-specific source: keep a long run's checklist in a file that survives compaction, and review a diff before it goes to a human reviewer (a client PR) |
| **C** | Delegate-by-default for the work itself: "2+ independent tasks means parallel agents", "always use subagents", pushing implementation down by reflex | Anthropic's 5.5 and Sonnet 5 pages give no delegation guidance beyond the point above. Delegate large, genuinely independent tracks; do not delegate what a handful of your own tool calls finishes. Anthropic says an Opus model is the better choice for the hardest long-horizon work. Its generic effort table (not the Sonnet 5.5 section, which never mentions subagents and overrides the table where they differ) lists `low` effort for "subagents", so a subagent tier is a cost decision to make on purpose |
| **D** | Re-check instructions: "double-check your answer", "re-verify before responding" | Nothing. Two vendor lines exist and neither applies to interactive work at `medium` or above: "Think carefully through the problem before responding" (Sonnet 5 page, for keeping effort at `low`) and "Think the problem through before you answer" (5.5 page, only for JSON answers under structured outputs with adaptive thinking). From `medium` up the 5.5 model already thinks briefly before almost every reply |
| **E** | Mandatory-invocation thresholds: "1% chance means you MUST invoke", "before ANY response", two-document rituals for small tasks | Invoke a skill when the task is one it covers. A skill check never gates a clarifying question. **LOCAL extension**; Anthropic states no rule here |
| **F** | Fixed-template padding in deliverables: required Bottom Line / Key Principles / Real-World Impact sections | Match length to what the task needs. The Sonnet 5 page says the model "calibrates response length to the complexity of the task"; the 5.5 page is silent on length, so that statement carries. Prompt for concision if a style needs it |
| **G** | Instructions to reproduce, echo, transcribe or "show" internal reasoning as response text, or to write reasoning out as a substitute for thinking | Nothing. These trip the `reasoning_extraction` classifier, and server-side fallback does not retry that category. Read thinking blocks if visibility is needed |

**Supplied by the harness on Sonnet 5.5 (observed in the main-thread system prompt of the release-day session, Claude Code 2.1.284; subagent prompts not checked); do not restate:** act when you have enough information (no re-deriving, no re-litigating, no surveying options you will not pursue); report outcomes faithfully, including failures and skipped steps; confirm before hard-to-reverse or outward actions; the `<pasted_content>` rule; the memory rules; "you don't need to wrap up early" on context; and the mid-turn "the user hasn't heard from you in a while" reminder, which is the 5.5 page's progress-update lever (it arrived live in this session). **Not supplied:** Anthropic's "keep working until everything is done" paragraph, its "don't add unrequested extras" paragraph and its "ideas means stop" paragraph. The three local lines below carry them.

**Three local lines, because Sonnet 5.5 has the behavior and the harness does not cover it.** (1) *Turn endings.* Live at `low` and `medium` effort only: on long agentic tasks the model is "more likely to stop and check in with the user before it finishes", to confirm a plan, to ask what it could answer itself, or to stop after one part of a multipart task. Anthropic's first fix is a higher effort level; its second is the vendor wording that follows. Keep working until everything the user asked for is done, and stop to ask only when you cannot go on without the user or before a risky, irreversible or outward step (the push gate). Local addition, no vendor source: put status notes and recommendations in the same message as the next tool call. (2) *Scope.* The model adds tests, docs and small supporting files at every effort level, more at higher effort. When the work asked for is done and checked, stop and report; a feature, test, file, doc or refactor that was not asked for goes in one closing sentence, not in the diff. (3) *Ideas are not a build order.* When the user asks for ideas, options or a plan, give that and stop; do not start building or changing anything until they say go.

**Effort.** Sonnet 5.5's levels are recalibrated against Sonnet 5, so a level does not mean the same thinking: run a fresh sweep, do not carry a setting over. The vendor default is `high` on the API and `medium` in Claude Code and the apps. For agentic coding and multistep tool use start at `medium` for well-specified tasks and move to `high` for harder or longer ones; `low` or `medium` for chat and latency-sensitive work. Reserve `xhigh`/`max` for work where a quality gain was measured: at those levels the model is thorough to the point of self-started review rounds. To get less thinking, lower effort; a prompt asking it to think less does not reliably work. Effort applies to every output token (text, tool calls and thinking), and higher effort also does more than asked, so it is not a scope control: use the scope line above. `thinking: {"type": "disabled"}` is a 400 error on 5.5; the API-level lowest setting is `between_tools` (not relevant to Claude Code sessions).

**Model choice.** Sonnet 5.5 is priced at half of Opus 5.5 ($2/$10 against $4/$20 per million tokens; cache reads $0.20 on both). Anthropic's own position: for the hardest long-horizon work, an Opus model is the better choice. **Local routing for well-specified agentic coding** (adopted by the user 2026-09-28 from Anthropic's Terminal-Bench 4.0 chart for 5.5; values read off the chart, Opus effort labels inferred from point order, one benchmark): default Sonnet 5.5 `high`; Sonnet `medium` for small, fully specified edits; step up to Opus 5.5 `medium` when Sonnet `high` stalls or the task is unfamiliar, and to Opus `high` when a miss is expensive (client PRs, push-gate work, security-sensitive code); `xhigh`/`max` only where a gain was measured on this user's work. On the chart Opus `max` scores below Opus `xhigh`, and Sonnet `xhigh` scores below Opus `high` at a higher cost, so neither is a default step.

**Precedence that makes it work:** user instructions (this file) outrank skills, which outrank default behavior. No plugin needs to cooperate.

**Expiry.** Each class is retired when Anthropic's guidance for the current model no longer supports it, not when any particular plugin changes. Plugin updates trigger a re-scan, not a re-derivation. Recorded per audit in the ledger.
